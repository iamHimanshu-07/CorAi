Deployment & operations

Plain-English guide to the two things operators ask about most: why is /metrics empty? and how do I turn on the chatbot?

1. Generate the model evaluation report

The /metrics page reads ml/evaluation/report.json plus per-model PNGs (ROC curves, confusion matrices, calibration, SHAP summary). The trained model artifact (models/corai-1.0.0.pkl) ships with the repo so predictions work without retraining, but the diagnostics have to be regenerated.

On Render free tier you don't have shell access, so the canonical command

python -m ml.train --data heart.csv --version 1.0.0

can't be run by hand. Use the in-app admin button instead:

  1. Log in as the bootstrap admin (default username doctor, password corai2026; promote to admin via flask --app 'app:create_app()' create-user --username you --role admin).
  2. Open /metrics. The page shows a blue Run training now panel (admin only).
  3. Click it. The training runs in a background thread inside the web worker. Refresh /metrics after 30-90 s — Render free is slow.
  4. Watch progress at /metrics/train_status (JSON snapshot).

Note: training peaks at ~300-400 MB RAM. On free tier (512 MB cap) it's tight but works because the training runs in a worker that's already loaded with sklearn; if it OOMs, switch to a Starter+ plan.

2. Enable the HeartAI Copilot chatbot

The floating chat widget on every authenticated page supports two backends. Pick one:

Option A — Google Gemini (recommended)

  1. Get a free API key at aistudio.google.com/apikey.
  2. On Render: Environment → Add Environment Variable:
    • Key: GOOGLE_API_KEY
    • Value: your key
    • Mark as secret.
  3. Trigger a manual deploy (or push to main). The chat widget picks up the new key automatically — no rebuild required, gunicorn workers re-read env on each chat request.

RAM caveat: the full RAG stack (langchain + faiss-cpu + sentence-transformers + torch) needs ~700 MB RAM at boot. The current slim requirements.txt ships without it to fit Render free (512 MB cap). To enable RAG on Render free you must either upgrade to a plan with ≥1 GB RAM and uncomment the RAG block in requirements.txt, or deploy to a host with more RAM (Render Starter+, Fly.io, Railway, a VPS).

Option B — OpenAI (lighter weight)

  1. Get an API key from platform.openai.com/api-keys.
  2. On Render, add:
    • Key: LLM_API_KEY
    • Value: your key
    • Key: LLM_MODEL  ·  Value: gpt-4o-mini (or any model you have access to)

OpenAI works on Render free because the openai package is already in requirements.txt and only loads on a chat request (not at boot).

3. Where Render puts env vars

Render injects env vars into the running container at boot. To set them:

  1. Open the CorAi service on the Render dashboard.
  2. Click Environment in the left sidebar.
  3. Click Add Environment Variable. The keys already wired in render.yaml (SECRET_KEY, BOOTSTRAP_DOCTOR_PASSWORD) auto-generate on first deploy; everything else you add here manually.
  4. After saving, click Manual Deploy → Deploy latest commit (or just push to main).

Heads up: changes to non-secret env vars don't always trigger an auto-deploy, so plan on a manual deploy after adding them.
